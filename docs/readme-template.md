## Чому цих розділів достатньо для першого запуску

Призначення визначає очікувану поведінку; вимоги й запуск прибирають приховані
передумови; параметри дозволяють змінити приклад. Коди виходу потрібні для
shell-скриптів, приклад виводу — для перевірки очікувань, обмеження — для вибору
придатного застосування. Вхід/вихід і побічні ефекти запобігають втраті даних.

## Що додала перевірка на curl

Після читання `curl --manual` до мінімальних семи розділів додано:

1. **stdout, stderr та побічні ефекти**: `--output` перезаписує файл, тоді як
   прогрес і помилки йдуть у stderr, а тіло за замовчуванням — у stdout.
2. **HTTP-статус окремо від коду процесу**: без `--fail`/`--fail-with-body`
   відповідь 404 може завершити curl із кодом 0.
3. **Мінімальну версію конкретного прапорця**: `--fail-with-body` з'явився
   у 7.76.0; на старій машині приклад не запуститься.
4. **Часовий бюджет та повтори**: `--max-time` обмежує одну спробу;
   для повторів також потрібен `--retry-max-time` і аналіз ідемпотентності.
5. **TLS, конфігурацію й секрети**: не вимикати перевірку сертифіката;
   `--disable` як перший аргумент прибирає вплив особистого `.curlrc`.

Джерело: [curl man page](https://curl.se/docs/manpage.html), розділи
`--disable`, `--fail-with-body`, `--output`, `--retry`, `EXIT CODES`.
