# curl: відтворюваний HTTP GET

Приклад заповнення шаблону README. Це опис наявної утиліти, а не власний застосунок.

## Призначення

Отримати HTTP-ресурс із командного рядка й перевірити успіх у shell-скрипті.
curl підтримує багато протоколів; цей приклад обмежено HTTP GET.

## Вимоги й установлення

Потрібні curl **7.76.0+** для `--fail-with-body`, POSIX shell і Python 3 для
локального тестового сервера. Версію перевірити командою `curl --version`.
В Ubuntu/Debian пакет встановлюється через `sudo apt-get install curl`;
у підготовленому хмарному середовищі curl уже є. Для локального тесту доступ
до Інтернету й облікові дані не потрібні.

## Запуск

У новій тимчасовій теці створити файл і запустити сервер:

```sh
fixture=$(mktemp -d)
printf '{"status":"ok"}\n' > "$fixture/health.json"
python3 -m http.server 8000 --bind 127.0.0.1 --directory "$fixture"
```

В іншому терміналі виконати:

```sh
curl --disable --silent --show-error --fail-with-body \
    --noproxy 127.0.0.1 --connect-timeout 2 --max-time 5 \
    'http://127.0.0.1:8000/health.json'
```

URL взято в одинарні лапки, щоб shell не трактував `&`, `?` або `*`.
Якщо порт зайнятий, оберіть інший в обох командах. Сервер після перевірки
зупиніть `Ctrl+C`, а власний файл і тимчасову теку видаліть.

## Параметри

| Параметр | Типове значення | Дія |
| --- | --- | --- |
| URL | немає, обов'язковий | адреса ресурсу |
| `--disable` | особистий curlrc читається | першим аргументом вимикає стандартний файл конфігурації |
| `--silent --show-error` | прогрес увімкнено | приховує прогрес, зберігає повідомлення про помилки |
| `--fail-with-body` | HTTP 4xx/5xx не дають помилки процесу | код 22 для HTTP-помилки зі збереженням тіла |
| `--connect-timeout 2` | без цього обмеження | до 2 секунд на встановлення з'єднання |
| `--max-time 5` | без цього обмеження | до 5 секунд на одну спробу передачі |
| `--noproxy 127.0.0.1` | залежить від конфігурації | локальна перевірка оминає зовнішній HTTP-проксі |
| `--output PATH` | тіло в stdout | записує тіло в PATH, може перезаписати наявний файл |
| `--write-out '%{http_code}'` | вимкнено | окремо друкує HTTP-статус у stdout |

Для зовнішнього ресурсу за потреби додають `--location`: він слідує редиректам.
Не використовуйте `--location-trusted` без аналізу передачі облікових даних.
Повтори автоматично не ввімкнені. Для ідемпотентного GET можна обмежено додати
`--retry 2 --retry-max-time 15`; для операцій зі зміною стану повтори небезпечні.

## Вхід, вихід і побічні ефекти

Вхід — URL, stdin у прикладі не читається. У stdout — тіло відповіді (байти,
не гарантовано UTF-8), у stderr — повідомлення про помилки. GET створює мережевий
запит і може потрапити в журнали сервера. `--output` створює або перезаписує
файл навіть тоді, коли тіло належить HTTP-помилці: це слід перевіряти кодом виходу.

## Коди виходу й обробка помилок

| Код | Значення | Дія |
| --- | --- | --- |
| 0 | передача виконана | перевірити потрібний вміст/HTTP-статус |
| 6 | не визначено IP хоста | перевірити адресу, DNS і мережу |
| 7 | з'єднання не встановлено | перевірити порт і доступність сервера |
| 22 | HTTP-помилка з `--fail-with-body` | прочитати HTTP-статус і тіло |
| 23 | помилка запису | перевірити права й вільне місце |
| 28 | сплив таймаут | перевірити затримки й часовий бюджет |
| 60 | сертифікат TLS не пройшов перевірку | виправити довіру/сертифікат, зберігши TLS-перевірку |

Відсутній файл дає реальну помилку:

```sh
if curl --disable --silent --show-error --fail-with-body \
    --noproxy 127.0.0.1 --max-time 5 'http://127.0.0.1:8000/missing'; then
    printf 'unexpected success\n'
else
    code=$?
    printf 'curl exit=%s\n' "$code"
fi
```

Очікується `curl exit=22`. Тіло 404 від `http.server` — HTML, воно також
залишається у stdout. Без `--fail-with-body` той самий 404 повертає код процесу 0.
Не приховуйте код curl останньою командою конвеєра; зберігайте його відразу.

## Приклад виводу

Для `health.json` із наведеними даними stdout:

```json
{"status":"ok"}
```

Код процесу — 0, HTTP-статус — 200, stderr порожній. Актуальна перевірена
версія й результати успішного та помилкових запитів — в
[журналі перевірки](../../assets/curl-validation.txt).

## Безпека й конфігурація

Перший аргумент `--disable` робить приклад незалежним від `.curlrc`.
На зовнішні запити можуть впливати `http_proxy`, `https_proxy`, `ALL_PROXY`,
`NO_PROXY` та налаштування CA; явні параметри й вибір протоколу слід перевіряти
в документації встановленої версії. Тут `--noproxy` потрібен лише для loopback.
У HTTPS зберігайте перевірку сертифіката; не використовуйте `--insecure`.
Не додавайте паролі/токени в URL, командний рядок, приклади README або Git.

## Обмеження

Код 0 не підтверджує бізнес-вміст JSON і без fail-прапорця не гарантує HTTP 2xx.
Цей приклад не перевіряє JSON-схему, не обмежує розмір тіла й не описує POST,
автентифікацію чи роботу з FTP. Таймаути потребують адаптації для реальної мережі.

## Перевірка й джерела

Перевірено три випадки: GET 200 → код 0 і очікуване тіло; GET 404 із
`--fail-with-body` → код 22 зі збереженим тілом; GET 404 без нього → код 0.
Джерела: `curl --manual` (вбудована man-довідка),
[офіційна man page](https://curl.se/docs/manpage.html).
