# Team DevOps Handbook

Практичний довідник для консольних утиліт курсу та лабораторної №2 з Git.

## Учасник і відповідальність

| Учасник | Роль | Розділи |
| --- | --- | --- |
| [@w1xes](https://github.com/w1xes) | автор і власник коду | усі розділи `docs/` |

Робота виконується одноосібно. Рецензент — GitHub Copilot, коли він доступний
для репозиторію. Незалежних учасників та людських схвалень ця адаптація не
імітує. Один автор не може незалежно написати версії «не дивлячись на чужі
гілки», тому конфлікт відтворюється двома альтернативними гілками одного автора.

## Робочий процес

1. Створити `feature/w1xes-<тема>` від актуальної `main`.
2. Встановити локальні хуки: `sh scripts/install-hooks.sh`.
3. Внести тематичні коміти, перевірити `python3 -m unittest discover -s tests -v`.
4. Відкрити окремий PR, запросити Copilot, обробити змістовні зауваження
   окремими комітами без переписування прорецензованої історії.
5. Дочекатися CI й завершення обговорень, виконати squash merge зі змістовним
   повідомленням Conventional Commits.

Потрібні Git, Python 3.10+ і POSIX shell. Це документаційний репозиторій:
застосунку, сервера та виробничих секретів немає. Для вправ потрібні також
`curl`, `tar`, компілятор C і Python-пакет `EditorConfig==0.17.1`.

## Конвенції та автоматизація

- [Гілки, коміти та встановлення хуків](docs/branching.md).
- `pre-commit` відхиляє кінцеві пробіли в індексі, `commit-msg` перевіряє формат.
- CI повторює перевірки; локальні хуки не є засобом захисту від обходу.
- `python3 scripts/changelog.py --output CHANGELOG.md` генерує список змін
  за історією поточної гілки. Згенерований файл ігнорується.

## Соло-правила

Для `main` передбачено обов'язковий PR, заборону force-push і видалення,
відсутність обходу для адміністратора та обов'язкове закриття обговорень.
Кількість обов'язкових людських схвалень — **0**, вимога схвалення CODEOWNERS
вимкнена за погодженою соло-адаптацією. Copilot не заміняє необхідне GitHub
людське схвалення; `CODEOWNERS` визначає фактичного власника файлів.

Результати, посилання на PR і відхилення від групової умови буде зібрано у
звіті лабораторної. Автоматичне проходження перевірок саме по собі не доводить,
що рецензування відбулося; усна перевірка залишається обов'язковою.
