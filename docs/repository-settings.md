# Правила GitHub і межі соло-адаптації

## Погоджена конфігурація

Репозиторій публічний, єдиний учасник і CODEOWNER — @w1xes. Для соло-виконання
обов'язкові людські схвалення й схвалення CODEOWNERS вимкнені. Решта правил
має застосовуватися до адміністратора так само, як до інших користувачів.

Підготовлений точний запит API: [ruleset-requested.json](../assets/ruleset-requested.json).

| Параметр | Значення |
| --- | --- |
| Назва | `main-solo-lab2` |
| Enforcement | `Active` |
| Ціль | `refs/heads/main` |
| Bypass list | порожній, адміністраторів також не додавати |
| Require a pull request before merging | увімкнено |
| Required approvals | `0` (погоджене відхилення від групової умови) |
| Dismiss stale pull request approvals | увімкнено |
| Require review from Code Owners | вимкнено (соло) |
| Require conversation resolution | увімкнено |
| Block force pushes | увімкнено |
| Restrict deletions | увімкнено |
| Require status checks | `handbook`, гілка має бути актуальною |

У **Settings → General → Pull Requests** залишити `Allow squash merging`;
для однозначного процесу вимкнути merge commits і rebase merging.

## Чого поточна інтеграція не змогла застосувати

Запити створення ruleset та редагування налаштувань репозиторію повернули
`403 Resource not accessible by integration`. Перевірка репозиторію показує
адміністративну роль власника, проте сама інтеграція не має необхідного дозволу
на зміну цих налаштувань. Доступ до Git, PR і рев'ю працює; додатковий токен
для цієї роботи не вимагається.

[rulesets-observed.json](../assets/rulesets-observed.json) — фактична відповідь
API після невдалої спроби: список правил порожній. **Ruleset ще не активовано**;
JSON із бажаною конфігурацією не є доказом захисту гілки.

Власнику треба у **Settings → Rules → Rulesets → New branch ruleset** застосувати
таблицю вище, зробити справжній скріншот налаштувань і додати його в `assets/`
окремим PR. Знімок налаштувань не підміняється намальованим зображенням чи
скріншотом JSON. Відсутній скріншот і незастосоване правило — відкриті вимоги
пункту 1 лабораторної.

Якщо інший авторизований користувач запускає API-запит:

```sh
gh api --method POST repos/w1xes/team-devops-handbook/rulesets \
    --input assets/ruleset-requested.json
gh api repos/w1xes/team-devops-handbook/rulesets
```

Спочатку перевірте поточні rulesets і не створюйте дублікати. JSON призначений
для створення лише відсутнього ruleset. Не додавайте bypass, щоб тимчасово
обійти правила; усі наступні зміни мають проходити через PR.

## Що залишається груповою вимогою

Copilot не зараховується як обов'язкове людське схвалення GitHub; автор не може
схвалити власний PR. Немає вигаданих collaborators, чужих авторств або заяв про
незалежне написання альтернативних конфігурацій. Для буквального виконання
групової умови потрібні реальні учасники й погодження викладача щодо соло-формату.
