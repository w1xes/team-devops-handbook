# Правила GitHub і межі соло-адаптації

## Активний ruleset `main-lab2`

Репозиторій публічний, єдиний учасник і CODEOWNER — @w1xes. Для соло-виконання
обов'язкові людські схвалення й схвалення CODEOWNERS вимкнені. Решта правил
застосовуються до адміністратора так само, як до інших користувачів.

Власник вручну додав ruleset **20 жовтня 2026 року**. Його наявність і
параметри повторно перевірено через GitHub API після отримання скріншота.
Ідентифікатор — `25502462`,
[сторінка правил на GitHub](https://github.com/w1xes/team-devops-handbook/rules/25502462).

Докази в репозиторії:

- [Повна конфігурація `main-lab2`](../assets/ruleset-main-lab2.json), включно з
  `bypass_actors: []` та `current_user_can_bypass: "never"`.

## Що підтверджує наданий скріншот

На наданому власником скріншоті відкрито **Settings → Rules → Rulesets**
репозиторію `w1xes/team-devops-handbook`. Видно запис **main-lab2** із зеленим
індикатором і підписом **4 branch rules · targeting 1 branch**.

Це оглядовий екран: він не показує список обходу й параметри кожного правила.
Їх підтверджено окремо повною відповіддю API вище. Чотири правила — це заборона
видалення, заборона force-push, вимога PR і вимога status checks; налаштування
схвалень та обговорень є параметрами правила PR.

Скріншот надано в чаті; оригінал не доступний у робочій файловій системі.
Щоб сам репозиторій містив передбачений лабораторною графічний доказ,
його PNG/JPEG-копію ще потрібно додати до `assets/` окремим комітом.
Наявність зображення в `assets/` цим описом не заявляється.

## Повторна перевірка й історія налаштування

```sh
gh api repos/w1xes/team-devops-handbook/rulesets
gh api repos/w1xes/team-devops-handbook/rulesets/25502462
```

Початкові спроби інтеграції створити ruleset і змінити налаштування репозиторію
повернули `403 Resource not accessible by integration`. Власник усунув цей
блокер ручним створенням правила. Попередній порожній список rulesets збережено
в Git-історії; актуальний `rulesets-observed.json` містить активний `main-lab2`.

[ruleset-requested.json](../assets/ruleset-requested.json) залишено як
**історичний проєкт** із назвою `main-solo-lab2`. Це не поточний ruleset, і
повторно створювати його не потрібно. Не додавайте bypass для обходу правил;
наступні зміни мають проходити через PR.

Для редагування відкрийте **Settings → Rules → Rulesets → main-lab2**.
Після змін повторіть read-only перевірку API й оновіть збережені докази.

## Що залишається груповою вимогою

Copilot не зараховується як обов'язкове людське схвалення GitHub; автор не може
схвалити власний PR. Немає вигаданих collaborators, чужих авторств або заяв про
незалежне написання альтернативних конфігурацій. Для буквального виконання
групової умови потрібні реальні учасники й погодження викладача щодо соло-формату.
